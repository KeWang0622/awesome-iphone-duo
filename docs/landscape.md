# Related directories and this project's focus

Checked **October 26, 2026**. These are complementary places to discover apps, inspect compatibility claims, and learn from existing catalogs. This comparison describes the public pages we read; it is neither an exhaustive survey nor a test of their apps.

| Project | Observed focus and strengths | Useful complementary work here |
| --- | --- | --- |
| [FoldHunt](https://foldhunt.com/) · [method](https://foldhunt.com/about/) | App and game discovery, pose categories, ideas, guides, and dated evidence with distinct developer, store, simulator, and device labels. Its method explicitly distinguishes simulator material from physical testing. | Keep a forkable field guide with feature-level citations, setup requirements, and reproducible workflow records. |
| [FoldCheck](https://foldcheck.org/) · [method](https://foldcheck.org/how-it-works) | Compatibility tracking using release dates, release notes, and version-specific owner reports; its method explains how those signals affect a verdict. | Explain what a documented feature enables and keep a support statement separate from a completed task. |
| [iPhone Duo Apps](https://appsforiphoneduo.com/) · [method](https://appsforiphoneduo.com/methodology) | Editorial collections, practical guides, source-scoped profiles, a shortlist/comparison flow, and visual tools. Its method explicitly discloses AI assistance and distinguishes source research from hands-on testing. | Package related research as editable data, command-line queries, recipes, and reviewable Git changes. |
| [DuoDiscover](https://duodiscover.com/launch) | A dated launch tracker links Apple announcements and developer release sources, alongside app search and categories. | Follow discovery with prerequisites and a concrete task to try. |
| [Made for Duo](https://madeforduo.app/apps) | Search by app or developer and simple full-screen, mostly-filled, and letterboxed classifications; submissions support community discovery. | Describe interactions such as separate controls, facing pages, or hinge input in addition to visual fit. |
| [Duo App Support](https://duoappsupport.com/) | A third-party app support matrix with unverified, limited, and fuller-support states; contributors can supply screenshots or release notes. | Attach an exact source and scope to each interesting capability, and retain independently stated availability. |
| [iPhoneApplicationList](https://iphoneapplicationlist.com/iphone-duo-apps/) | Searchable support directory with versioned App Store evidence, category/rating sorting, a downloadable list, and stated refresh methodology. | Curate task choices and explain hardware, host, protocol, and service requirements. |
| [mergisi/awesome-iphone-duo](https://github.com/mergisi/awesome-iphone-duo) | Developer-oriented list whose current README introduces the runnable Hello Duo SwiftUI sample and welcomes additions. | Cover consumer workflows and interesting apps while linking relevant implementation resources. |
| [Open-Source iOS Apps](https://github.com/dkhamsing/open-source-ios-apps) | Broad collaborative source-code catalog, including Duo projects, with structured metadata and generated views. | Explain why a Duo project is interesting and distinguish a source build from an installable release. |
| [Awesome Mac](https://github.com/jaywcjlove/awesome-mac) | Mature software list organized by purpose with concise entries and availability/source indicators. | Apply that readable format to Duo's particular interactions and setup choices. |

Evidence labels, comparisons, downloadable data, and practical guides already exist in this landscape. The contribution here is the package: a forkable catalog and dependency-free Python tooling, source links for specific features, a local-versus-remote laptop guide, workflow recipes, and a format for reproducible test records. Those choices express this project's focus; they do not establish that a feature is unique online.

The laptop guide is a useful starting point because “turn it into a laptop” can mean several different things: control another computer, use a browser workspace on the phone, emulate a guest system locally, or connect to a remote shell. Those paths have different requirements and limitations. A larger screen or a keyboard-shaped interface alone does not establish that desktop software runs locally.

The initial catalog is source-researched. A test recipe is a proposal until someone records its execution, environment, and result. See [research and evidence](research.md) for that distinction and [the catalog](../README.md) for app-level sources. Use the linked directories to discover additional candidates, then follow their references to the original developer, platform, or release documentation.
